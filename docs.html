01

Introdução e Motivação

Este trabalho acadêmico, desenvolvido para a disciplina de Redes Neurais, aborda a predição de óbito de pacientes diagnosticados com COVID-19 usando um classificador de Perceptron Multicamadas (MLP). A tarefa é formulada como um problema de classificação binária supervisionada: dado um conjunto de atributos clínicos do paciente, o modelo deve prever se o desfecho será sobrevivência (classe 0) ou óbito (classe 1).

O principal desafio do projeto é o severo desbalanceamento de classes: apenas 7,34% dos registros correspondem a óbitos (proporção aproximada de 13:1). Isso exige que a estratégia de avaliação priorize métricas além da acurácia bruta, em especial o F1-Score e o Recall da classe positiva.

⚠️ Problema clínico: Em contexto médico, um falso negativo (não detectar um óbito iminente) é mais custoso que um falso positivo. Portanto, maximizar o recall da classe de óbito é prioritário, mesmo que isso implique redução da acurácia geral.

Definição da Variável Alvo

A coluna DATE_DIED indica a data de óbito quando preenchida, ou NaN caso contrário. A variável alvo binária foi criada como: morte = 1 se DATE_DIED preenchida; 0 se NaN . A coluna DATE_DIED foi então removida do conjunto de features para evitar data leakage.

Pipeline de Desenvolvimento

1
📥 Ingestão do Dataset
Carregamento do arquivo CSV do Kaggle. 1.048.575 registros, 21 colunas.
2
🎯 Criação da Variável Alvo
morte = (DATE_DIED.notna()).astype(int) — 1 = óbito, 0 = sobreviveu
3
🧹 Limpeza dos Dados
Remoção das 6 colunas indicadas. Valores 97 e 99 (código de "não informado" no dataset) são substituídos por NaN. Registros com qualquer NaN são descartados via dropna().
4
🎲 Amostragem Estratificada
Seleção aleatória de 100.000 registros com random_state=42, mantendo a proporção das classes (stratified sampling) para preservar a distribuição do desbalanceamento.
5
⚙️ Pré-processamento
ColumnTransformer com StandardScaler para AGE e OneHotEncoder(drop='first') para as 14 features categóricas.
6
✂️ Divisão Treino/Teste
train_test_split(test_size=0.2, stratify=y, random_state=42) — 80.000 treino / 20.000 teste.
7
🧠 Treinamento do MLP
27 configurações testadas: 3 famílias de arquitetura × 3 tamanhos × 3 learning rates. MLPClassifier(solver='adam', max_iter=500, random_state=42)
8
🔍 Ajuste de Threshold
Aplicado ao melhor modelo. predict_proba substitui predict, e o limiar é reduzido abaixo de 0.5 para aumentar o recall da classe de óbito.
9
📊 Avaliação
Métricas: Acurácia, F1-Score ponderado, Recall cls.1, Precisão cls.1, Matriz de Confusão.

Ajuste de Threshold

O limiar padrão de classificação no Scikit-learn é 0.5: a classe 1 é prevista quando predict_proba(X)[:, 1] ≥ 0.5. Em cenários com classes desbalanceadas, esse limiar é subótimo para a classe minoritária.

Ao reduzir o threshold (por exemplo, para 0.3 ou 0.35), o modelo torna-se mais "agressivo" na predição de óbito, aumentando o recall à custa de precisão. O F1-Score — que equilibra precisão e recall — é usado como critério de seleção do melhor threshold.

09

Conclusão

Este trabalho demonstrou que o ajuste de threshold é uma estratégia eficaz e de baixo custo computacional para lidar com desbalanceamento de classes em modelos de classificação binária. A abordagem mostrou-se superior ao simples aumento da complexidade arquitetural.

O modelo vencedor — MLP (16, 16) com learning_rate=0.001 — é notavelmente compacto (apenas 2 camadas ocultas de 16 neurônios) mas supera redes maiores como (64, 64, 64) no F1-Score. Isso reforça que, para features majoritariamente binárias com baixa dimensionalidade, arquiteturas simples generalizam melhor.

🏆 Resultado principal: Com o ajuste de threshold, o modelo atingiu 73.55% de recall para a classe de óbito e F1-Score de 0.5576, tornando-o viável para triagem clínica de risco de óbito por COVID-19.
